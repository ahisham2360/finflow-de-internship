# 1. What is a Data Engineer

A Data Engineer is someone whose main goal is to make unorganized raw data usable. They create and maintain systems that can be scaled in the future. These systems can process, organize, and store a huge amount of data that can reach exabytes (1,000,000,000,000,000,000) which exceeds what MySQL or Excel could handle.
## What a Data Engineer typically does:
- Setting up ETL pipelines
- Writing Python or SQL scripts
- Managing cloud infrastructure (AWS or GCP)
- Integrating APIs
- Working with a huge amount of data using tools like Apache Spark, Airflow, Kafka
## Data Engineer vs. Data Scientist vs. Software Engineer
- Software Engineer: They build apps, websites, and anything the user interacts with.
- Data Engineer: They use the data generated by these apps and make sure it flows smoothly until it is analyzed.
- Data Scientists: They predict what might happen next by using advanced math, models, and machine learning.



# 2. ETL vs ELT

## Extract Transform Load (Old)
This process extracts data from the source, then transforms data to a usable format, then transfers this usable data to be stored so it can be analyzed later.
Advantages:
- **Speed at end:** ETL is slower at start, but once transformation is done, using the data is very fast and easy.
- **Storage:** No need for much storage like ELT because you know exactly how much of the raw data will be stored after transforming it.
- **Example:** pulling old bank transactions, hiding the customer's credit card numbers for security first (transforming), and then saving them to the main bank database so they are ready to go.
## Extract Load Transform (Modern)
This process extracts data from the source, then immediately loaded into storage without being transformed, then it is transformed to a usable format directly from the data repository.
Advantages:
- **Availability:** more available than ETL as the data is stored as it is without making any transformation decisions, so later analysts can access any raw data that has been stored unlike in ETL.
- **Flexibility:** you can use data in new ways whenever you want, and the original data can be found and transformed with any method the analyst wants. ETL on the other hand is just a linear process, once a decision has been made to the data, it’s impossible to change it easily.
- **Scalability:** ELT is very scalable because you can instantly store huge amounts of raw data without having to process them first, while ETL must transform every byte of data before storage so it's hard to scale.
- **Speed at start:** Very quick loading time to store data, but it takes longer to transform the data so it's ready to be used.
- **Example:** moving millions of raw mobile money logs straight into storage as soon as they happen, and then using SQL to filter out the fraud ones later when the analysts actually need them.



# 3. Batch vs Streaming

## Batch Processing
Collecting a very large amount of data over a course of time and processing it at the end.
**Fraud Detection Example:** Running a batch process at midnight that analyzes all day's transactions to find a scammer who is stealing $5 from hundreds of accounts. This requires a lot of processing power so we must wait until system is not busy.
## Streaming Processing
Processing data the exact millisecond it's generated, so it's continuously processed in real-time.
**Fraud Detection Example:** Analyzing each credit card transaction in real-time, and if the card is being used in 2 different countries at the same time it is declined instantly.



# 4. Why pipelines need parallelism?

## Problem with sequential processing at scale
Sequential processing would be fine at a small scale, but doing tasks one by one at scale where we have millions of rows would take the pipeline hours to run. Parallelism allows you to divide data into parts and run them in parallel, saving a lot of time.
## concurrency tools Python offers
- **Threading (ThreadPoolExecutor):** Used in tasks mainly input & output, like reading from a database or downloading files from the internet. It is useful when the program is waiting for data to load.
- **Multiprocessing (ProcessPoolExecutor):** Used in tasks that are heavy on the CPU. We can exceed the maximum execution speed by creating separate processes that run simultaneously.
- **Asyncio:** A tool in python that handles a lot of network requests at the same time without freezing the main program.



# 5. The DE stack at a glance

**Source -> Ingest -> Transform -> Model -> Serve**

- **Source:** Where we get the raw data from.
- **Ingest:** Extracting the raw data from the source and moving it into our system (using batch or streaming).
- **Transform:** filtering and fixing the raw data so it is usable by removing errors and hiding sensitive information.
- **Model:** Organizing the transformed data into tables so it is easy to read & search.
- **Serve:** Delivering the final data to the people who need it (like Data Scientists).
